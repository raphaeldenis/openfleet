# Changelog

The MCP tool contract of the OpenFleet server. One section per `contract_version`; the convention is in `docs/mcp-contract.md`.

## Unreleased — no contract_version change

- TRG-RETENTION01 (daemon only; no tool, REST route, migration or `contract_version` change, which stays 15): the trigger ledger forgets the events of old fires. The event (`event_json`) of a `completed` or `cancelled` fire is emptied 90 days after it ended (`settled_at`); the row stays, with its dedup key, state and dates, so a source that offers the same event again (a session that stays `closed_with_error`, a `fire_all` backlog) gets the fire already settled and nothing runs twice, and a cooldown longer than the retention still counts the fire. An `accepted`, `attempted` or `needs_review` fire keeps its event. The purge runs at boot (after `recover()`) and every 24 hours on the scheduler of the daemon, whether or not a fire settles; it handles at most 1000 rows per statement, continues after the last row handled, hands the event loop back between two batches, and ends at the first batch that is not full. There is no cap on the number of rows: the retention is by age. New `config.json` key `triggers.fireRetentionDays` (whole number from 1 to 3650, default 90; an invalid value or an unknown key in `triggers` refuses the boot, like the other daemon settings). A failed purge is logged (`the trigger fires could not be pruned`) and changes nothing else. No migration. Cost with 100 000 rows, 70 000 of them forgotten: 71 batches (`fireRetention.cost.test.ts`). `docs/triggers.md` describes it.
- TLK-1 (REST and desktop; no tool added or reshaped, so `contract_version` stays 15 and `contract.pinned.json` does not move): `GET /api/tools` answers `{ items: [{ name, domain, category }] }`, sorted by name, from the tool catalog (`mcp/toolCatalog.ts`), so it lists the same tools an MCP client sees; it takes the admin token only (401 without a token, with a wrong one and with the MCP token of a session). It carries no description or input schema. The desktop Toolkit screen (`/toolkit`) shows the catalog by domain with a search, the category of each tool and the name Claude Code gives it (`mcp__openfleet__<name>`), and the known harnesses (Claude Code is supported, the others read "Unknown": the daemon reports no state for them). The policy matrix and the custom tools have no tab.

- ACTIVITY-LOG01, ACT-1 to ACT-3 and ACT-2b, with TLK-0 (daemon only; no tool added or reshaped, so `contract_version` stays 15 and `contract.pinned.json` does not move): migration `063_activity_log.sql` (down file `063_activity_log.down.sql`) adds the append-only table `activity_log`, and `GET /api/activity` reads it. A row says who (`actor_kind` human, agent or system; the label is `admin`, the session name, `daemon` or `scheduler`), when, from where (`source` mcp, rest, hook or daemon), what (`action`), the entity, the `outcome` (`ok`, `denied` or `error`) and the duration. Recorded: every MCP call of a tool that is not `read_only` in the new tool catalog (`mcp/toolCatalog.ts`, a domain and a category for each of the 72 tools; metadata only, nothing is enforced, and a test fails when a registered tool has no entry; an uncatalogued tool counts as mutating), filed under the root manager of the caller's lineage; every REST call that is not a GET, HEAD or OPTIONS and passed the admin token check, as a `human` row named `gate.decide`, `proposal.decide`, `law.edit`, `law.withdraw` or `command_policy.save` for those routes and `METHOD /api/route/:template` for the others (`POST /api/ws-ticket` is no action and is skipped; the request body is not logged); and the system rows `daemon.start`, `pulse.sent` (filed under the pulsed manager) and `session.resume` (one per session brought back at boot). Not recorded: reads, requests refused for their token, and anything before the migration. `denied` means a rule refused the caller (`unauthorized`, `outside_lineage`, `not_a_manager`, `backlog_write_refused`, `outside_own_repository`, `directory_not_in_project`, `base_not_read`, `note_not_read`, `findings_required`, `verdict_stale`, `criteria_stale`, `escalation_open`, `question_unclassified`, `manager_paused`, `row_guard_violation`, `message_held_for_review`); any other failure is `error`. The activity log stores no command and no free text, and keeps a value or a key only when it belongs to a closed set: a key is kept only when a registered mutating tool declares it in its input schema (top-level or nested, read once per tool) or it is a known result field, an identifier word or an enumeration word; any other key becomes `[key len=N]` (an index `#2`, `#3` keeps equal marks apart) and its value is hidden. Under a kept key the arguments keep numbers, booleans, UUIDs, identifiers under an identifier key and the members of the closed set of an enumeration key (`status`, `kind`, `category`, `outcome`, `role`, `harness`, `model`, `mode`, `decision`, `verdict`, `severity`, and `code` for the error codes), of at most 64 characters; every other text becomes `[text len=N]`, with no fingerprint. The result keeps `[result len=N]` and the scalar fields that pass the same list; the detail is an error code of the grammar, an error class name (`…Error`, `…Exception`) or the daemon version; the labels (`actor_label`, `entity_label`) are safe tokens and the ids (`session_id`, `manager_id`, `entity_id`) safe tokens or UUIDs, any other text becoming `[text len=N]`. Accepted limit: a secret shaped as a UUID or an identifier reads as one (bounds: arguments 400 characters, result 200, names 200). Writing is fail-open: a failed insert is logged as a warning and never fails the tool call or the REST call. Retention: the newest 100 000 rows and at most 90 days, pruned at boot and every 500 inserts; no route edits or deletes a row. `GET /api/activity?actor=&session=&manager=&entity=&action=&outcome=&since=&until=&limit=&cursor=` answers `{ items, nextCursor? }`, newest first, `limit` 1 to 200 (default 50), `cursor` the `nextCursor` of the previous page; it takes the admin token only (401 without a token, with a wrong one and with the MCP token of a session) and there is no MCP read tool and no WebSocket event. The cost of one recorded call, on a file database in WAL mode with pruning included, is measured by `activityRecorder.latency.test.ts` and stays under 2 ms. Limits: the `manager` filter matches the root manager of the lineage at write time, so rows of a session whose parent changed later keep their first manager; there is no REST route for the manager profile, so `profile.save` is not a named action.

- MANAGER-ARTIFACT-WRITE01, security (`contract_version` stays 15; no tool schema, REST view or migration change): each project with a docs folder gets `<docs folder>/artifacts/<manager>/`, created by the daemon, where a manager, its children and their sub-agents write with the `Write` tool without a prompt; nothing else is vouched for. The daemon answers the `PreToolUse` hook of a `Write` with `allow` only when the session descends from a manager of the project, the path is absolute and canonical (no `..`, `.`, `//` or NUL), its real path stays inside that manager's directory (a symbolic link that leaves it, or a link as the target, is refused), the content is a string, the file is within `artifacts.maxFileBytes` and the project's artifacts stay within `artifacts.maxProjectBytes`. A write in the directory that breaks one of these is answered `deny`. A path elsewhere, `Edit`, `MultiEdit`, `NotebookEdit`, `Bash`, `Read` and every `PermissionRequest` stay with the policy and the approval flow, as before; a policy refusal (for instance `no-write-into-git-dir`) still wins. The manager name becomes a directory name of ASCII letters, digits, `.`, `_` and `-` (64 characters at most, no leading `.` or `-`, `manager` when nothing is left), so two names that differ only by other characters share a directory. Every judged write adds one `session_events` row, kind `artifact_write` or `artifact_write_refused`, whose payload carries the session id, the actor (`manager` or `child`), the agent id of a sub-agent, the project, the manager name, the path and the byte count or the refusal reason. New `config.json` key `artifacts` (`maxFileBytes`, default 256 KiB, at most 512 KiB, under what a hook body can carry; `maxProjectBytes`, default 50 MiB, at most 1 GiB; a value that does not pass the schema is ignored with a warning and the defaults apply). The grant covers the root manager of the session's lineage, its children and sub-agents. It is given only when the policy allows the `Write` without observing a refusal: a policy `deny`, `ask` or observed refusal wins and is journaled as before. An existing target with several hard links is refused. A `Write` larger than the hook body the daemon reads (1 MiB, JSON escaping included) never reaches the judge and follows the normal approval flow. A folder the quota walk cannot read gives no opinion, never an `allow`. Limits: the judgement and the write are not atomic (a link planted in between is not caught; a child with `Bash` can already do the same in plain shell), and a write through `Bash` is not covered.

- USAGE-TOKENS-INGESTION01 (daemon behaviour, off by default; no tool schema, error code or migration change, `contract_version` stays 15): the daemon can record the token counts of a session's transcript at each `Stop` hook. It is off unless the daemon starts with `OPENFLEET_USAGE_INGESTION=1` (the exact value `1`; `DaemonOptions.usageIngestion`, default off). Only the file the session's own hook reported, after the daemon's trust checks, is read, and only the message id, timestamp, model and the four token counts are kept. Each `Stop` reads at most 1 MiB past the session's cursor (inode and offset, kept in memory): an incomplete last line waits for the next `Stop`, a line longer than the chunk or than 512 KiB is skipped, a transcript larger than the chunk is caught up over several `Stop` hooks, and after a daemon restart a transcript is read again from its start under the same cap per `Stop` (the upsert on session and message id never counts a message twice). A session ingests at most once per one-second window (`PerSessionTrailingThrottle`, monotonic clock): the first `Stop` of a window ingests at once and the `Stop` hooks that follow inside the window collapse into one trailing ingestion at its end, so the last `Stop` of a turn is delayed by up to one second and never dropped. The bound is per session (N sessions in a loop make N ingestions per second on the shared event loop), and an ingestion also reads up to 1 MiB and makes up to about 10 000 upserts. A message that the timestamp window, the bucket budget or the session maximum refuses is lost (the cursor moves past it). A session that closes inside its window loses its trailing ingestion, because its transcript path is forgotten before `session.closed` is emitted; a daemon shutdown instead runs the waiting trailing ingestions once before the sessions close, and ignores the `Stop` hooks that arrive after it began. No change of contract. A message id or model that does not match `^[A-Za-z0-9_.:-]{1,128}$`, or a count above 1 000 000 000, rejects its line; rejected lines are counted in one warning with a fixed message (`usage_lines_rejected`). The CPU of a `Stop` is bounded: a message dated before its session was created minus one day or after now plus one day is rejected, one ingestion touches at most 32 buckets, and a session stores at most 100 000 messages (it then warns once, `usage_session_full`, and reads nothing more). A skipped oversized line loses its tail up to the next line break. A failed ingestion counts toward the degraded state like the other hooks, at most once a minute per session, with a fixed log message that carries the session id and the code `usage_ingestion_failed`. See `docs/usage-ledger.md`.

## 7 — 2026-10-29

Scheduled manager events: a manager sends a message to itself at a chosen time.

- `schedule_argus_event` added: `{ message, title?, at | in_minutes }`. `at` is the user's local time without offset, `YYYY-MM-DDTHH:MM:SS` (e.g. `2026-10-31T09:30:00`); `YYYY-MM-DDTHH:MM` is accepted and reads as second 0. `at` and `in_minutes` together, a past time, an offset in `at`, a message above 8192 bytes and a 21st pending event are refused. At a clock change the platform resolves the local time silently: a time that does not exist (spring forward) lands one hour later, an ambiguous time (fall back) reads as its first occurrence.
- `list_argus_events` added: the pending events of the caller, soonest first.
- `cancel_argus_event` added: `{ event_id }`, only by the actor that scheduled the event.
- `get_argus_status` changed: the result gains `scheduled_events`, the caller's pending events (same shape as `list_argus_events`). Its input is unchanged.
- An event is delivered once through the persisted message queue as a line starting `[scheduled event …]`, distinct from `[pulse]`. It is delivered late, with `delivered late` in the line, when the app was closed at its due time. It is held while the manager is closed or paused, replayed on reopening or resuming, and waits for the end of a running turn. When the queue refuses the message, the due event stays pending and is retried 60 s later.

Tools added: `schedule_argus_event`, `list_argus_events`, `cancel_argus_event`.
Tools changed: `get_argus_status` (new output field `scheduled_events`).
Migrations: `049_argus_scheduled_events` (table `argus_scheduled_events`; down script in `packages/core/src/db/migrations-down/`).
